# Архитектура Provable

Provable — система проверки выводов из официальной статистики. Ниже: из чего она состоит, как проходят данные, как выносится вердикт и как проверено качество. Диаграммы рисуются прямо на GitHub.

## 1. Компоненты

```mermaid
flowchart LR
    subgraph DATA["Данные БНС (синтетические микроданные)"]
        D002["Д-002<br/>качество жизни"]
        D004["Д-004<br/>бюджет"]
        D006["Д-006<br/>жильё"]
        D008["Д-008<br/>состав семьи"]
    end

    subgraph PIPE["Конвейер (Python, run_all.sh, ≈5 минут)"]
        BD["build_dataset.py<br/>панель 23 884 домохозяйств"]
        EN["engine.py<br/>статистический движок"]
        FI["findings.py<br/>аудит 253 пар"]
        PL["eval/planted.py<br/>проверка метода"]
        BA["build_app.py<br/>сборка приложения"]
        EX["export_bns.py<br/>Excel для БНС"]
    end

    subgraph OUT["Результаты"]
        FJ[("findings.json<br/>вердикты и числа")]
        APP["provable.html<br/>офлайн-приложение"]
        XL["provable_для_БНС.xlsx"]
    end

    subgraph AI["ИИ-режим (по желанию, нужен интернет)"]
        SV["serve.py<br/>локальный сервер :8799"]
        LA["llm_api.py<br/>проверка ответа модели"]
        LLM(["Gemini → Groq<br/>бесплатные лимиты"])
    end

    D002 & D004 & D006 & D008 --> BD --> FI
    EN --- FI
    EN --- PL
    FI --> FJ --> BA --> APP
    FJ --> EX --> XL
    APP <-. "текст вопроса" .-> SV
    SV --> LA <--> LLM
```

| Компонент | Что делает |
|---|---|
| `build_dataset.py` | сшивает формы по ключу `NOMER` в панель домохозяйство × год: доходы, лишения, удовлетворённость, состав семьи, жильё |
| `engine.py` | ранговая корреляция по всем семьям и внутри ячеек регион × город/село × год, перестановочный тест, бутстрап, региональный тест на двух годах; разбор вопросов; проверка чисел в тексте |
| `findings.py` | применяет движок ко всем 253 парам показателей и проверяет главную находку на устойчивость |
| `provable.html` | интерфейс: вопросы, проверка утверждений и записок, генерация записки, библиотека выводов, графики |
| `serve.py` + `llm_api.py` | ИИ-режим: модель понимает вопросы и пересказывает вердикты; всё, что она вернула, проверяется кодом |
| `export_bns.py` | Excel для сотрудника без программирования |

## 2. Главный принцип: модель не считает

```mermaid
flowchart LR
    T["Текст вопроса"] --> M["Языковая модель<br/>или словарь"]
    M -->|"показатели + цитата"| C{"Проверка кодом:<br/>показатель в каталоге?<br/>цитата есть в тексте?"}
    C -->|"нет"| R["Отказ или словарь"]
    C -->|"да"| S["Статистический движок"]
    S -->|"вердикт и числа"| V["Ответ пользователю"]
    V --> X["Пересказ моделью"]
    X --> G{"Каждое число<br/>есть в расчётах?"}
    G -->|"нет"| B["Пересказ заблокирован"]
    G -->|"да"| O["Пересказ показан"]
```

Числа и вердикты всегда считает движок. Модель только понимает текст и пересказывает результат, и оба её выхода проверяются кодом.

## 3. Как выносится вердикт

```mermaid
flowchart TD
    A["Пара показателей"] --> B["ρ по всем семьям"]
    B --> C["ρ внутри ячеек<br/>регион × город/село × год"]
    C --> D{"Перестановочный тест<br/>p &lt; 0,01 и связь<br/>сохраняется?"}
    D -->|"да"| H["✓ HOUSEHOLD<br/>вывод о семьях допустим"]
    D -->|"нет"| E["ρ между 20 регионами<br/>в 2023 и 2024"]
    E --> F{"Знак совпадает<br/>и интервалы не<br/>включают ноль<br/>в обоих годах?"}
    F -->|"да"| R["◐ REGIONAL<br/>вывод только о регионах"]
    F -->|"нет"| N["✕ NONE<br/>вывод не делается"]
```

## 4. Вопрос в ИИ-режиме

```mermaid
sequenceDiagram
    actor U as Аналитик
    participant A as provable.html
    participant S as serve.py
    participant L as Gemini / Groq
    participant E as Движок (в приложении)

    U->>A: «Отражается ли безработица на ощущении достатка?»
    A->>S: текст вопроса
    S->>L: текст + каталог 23 показателей
    L-->>S: показатели с цитатами
    S->>S: проверка: каталог и дословная цитата
    S-->>A: «Число занятых» × «Самооценка достатка»
    A->>E: вердикт для пары
    E-->>A: ◐ только между регионами, ρ, ДИ, p
    A-->>U: вердикт, таблица доказательств, график по 20 регионам
    U->>A: «Қазақша түсіндіру»
    A->>S: факты вердикта
    S->>L: факты → пересказ
    L-->>S: текст на казахском
    S->>S: каждое число сверено с фактами
    S-->>A: пересказ или блокировка
```

Без интернета или без `serve.py` приложение использует словарь (русский и казахский) и работает так же, только без пересказа.

## 5. Проверка записки

```mermaid
sequenceDiagram
    actor U as Аналитик
    participant A as provable.html
    participant R as Правила понимания
    participant V as Проверка утверждения

    U->>A: текст записки
    A->>A: разбивка на предложения
    loop каждое утверждение
        A->>R: показатели, направление, «регионы/семьи», отрицание, доли словами, «всегда»
        R-->>A: структура утверждения
        A->>V: сверка с вердиктом пары и числами
        V-->>A: ✓ / ✕ с причиной / «не могу проверить»
    end
    A-->>U: 4 подтверждаются, 3 нет — по каждому причина
```

Утверждения проверяются только правилами, без языковой модели: на контрольном наборе с моделью проскочило одно ложное утверждение, без неё — ни одного.

## 6. Конвейер `run_all.sh`

```mermaid
flowchart TD
    S(["bash run_all.sh"]) --> A["build_dataset.py<br/>сырые CSV → панель"]
    A --> B["findings.py<br/>253 пары × 200 перестановок + бутстрап"]
    B --> C["eval/planted.py<br/>метод на данных с заложенным ответом"]
    C --> D["build_app.py<br/>provable.html"]
    D --> E["export_bns.py<br/>Excel"]
    E --> F["test_engine.py<br/>автотесты"]
    F --> G["eval/logic_eval.py<br/>логика на 1 533 утверждениях"]
    G --> Z(["Новое приложение и Excel"])
```

Новые микроданные → та же команда → новые вердикты. Ни одно число в коде не задано вручную.

## 7. Как проверено качество

```mermaid
flowchart LR
    Q["Качество"] --> M["Метод"]
    Q --> L["Логика проверки"]
    Q --> N["Понимание языка"]
    Q --> X["Пересказ моделью"]
    M --> M1["35 из 36<br/>данные с заложенным ответом"]

    N --> N1["Вопросы 30 из 30 с моделью<br/>(20 из 30 словарь)"]

```

Подробности и ограничения каждого замера — в [eval/README.md](../eval/README.md).
